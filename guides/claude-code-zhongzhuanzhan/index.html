Claude Code 接中转站：两个环境变量，和接完以后怎么确认是真 Claude

数据截至 2026-11-24（北京时间） · 来源：Veridrop 中转站检测的公开检测报告

接入只要两个环境变量

Claude Code 通过中转站使用，只需要设两个环境变量：

  • ANTHROPIC_BASE_URL：中转站的地址
  • ANTHROPIC_AUTH_TOKEN：中转站给的 key

一般写在 ~/.claude/settings.json 的 env 里：

{
  "env": {
    "ANTHROPIC_BASE_URL": "https://你的中转站地址",
    "ANTHROPIC_AUTH_TOKEN": "你的 key"
  }
}

改完重新打开 Claude Code，输入 /status，看“Anthropic base URL”一行是不是你填的地址。是，就说明配置生效了。

有一点要先确认：Claude Code 走的是 Claude 的原生接口（/v1/messages）。只提供 OpenAI 格式接口的中转站接不上。

接上了，不等于给的是真 Claude

Claude Code 做一个任务会连续发很多次请求。中间要是被换成了别的模型，代码照样写得出来，差别很难凭感觉看出来。

所以接完以后有两个问题要回答：

  1. 背后是不是真的 Claude。
  2. 工具调用稳不稳。Claude Code 读文件、改文件全靠工具调用，这一项不稳，任务会中途报错。

这两个问题怎么查

Veridrop 中转站检测测的就是 Claude Code 用的这套接口。它是一个开源的检测工具，填中转站地址、key 和模型名，一分钟左右出一份报告。

和 Claude Code 直接相关的两项：

思维签名。 Claude 开启思考以后，响应里会带一段签名，由 Anthropic 服务端生成。中转站把请求转给别的模型，就拿不到它。这是判断“是不是真 Claude”最直接的一项，在 Veridrop 的 Claude 检测里权重最高。

工具调用。 强制模型调用一次工具，看返回的格式对不对。

检测过的 Claude 中转站 5,630 家
Claude 协议的检测报告 85,583 份

换句话说，每 8 次思维签名检测里大约有 1 次没过。

多少家两项都稳

Veridrop 给 Claude Code 单独列了一份名单，入选条件是四条：

  • 在 Claude 榜进入排名；
  • 思维签名通过率在 80% 以上，至少测过 3 次；
  • 工具调用通过率在 80% 以上，至少测过 2 次；
  • 最近 30 天内测过。

截至 11 月 24 日，名单列满了 30 家。名单每天更新，当天的见 Claude Code 中转站名单。

名单之外的站不代表不能用，可能只是检测次数不够。

检测没有覆盖的

这一点要说清楚。Veridrop 测了模型真假、一次强制的工具调用、用量字段、流式和非流式输出是否一致、响应格式。下面这些它没有测：

  • Claude Code 的长会话和子代理；
  • 提示缓存有没有生效；
  • 模型长时间思考时，连接会不会被中转站断掉；
  • 长上下文。这一项只在提交检测时勾选才跑。

所以检测通过说明的是“这家站的 Claude 看起来是真的，工具调用也稳定”，不等于“Claude Code 的每项功能都正常”。

这些没覆盖的部分，和中转站的转发方式有关。按 Claude Code 官方给网关的兼容性说明，中转站需要做到：

  • 原样转发 anthropic-beta、anthropic-version 两个请求头；
  • 流式响应边收边转，并保留其中的 ping 事件；
  • 原样转发缓存标记和上游的错误信息。

做不到的站，会出各种不好查的问题。充值之前可以直接问中转站这三条。

接完以后的四步

  1. 用同样的地址、key 和模型名，在 Veridrop 上测一次。
  2. 在 Claude Code 里输入 /status，确认地址是你的中转站。
  3. 让它做一个要读文件、改文件的小任务，看会不会中途报工具调用的错误。
  4. 过一段时间再测一次。中转站可能会换后端。
