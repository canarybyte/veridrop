先分清两类东西

这里说的 GPT 中转站，指提供 OpenAI 接口的 API 中转站：在自己的代码、Codex、Cherry Studio 这类客户端里填它的地址和 key，就能调用 GPT 模型。

ChatGPT 网页版的共享账号、镜像站是另一类服务，不在这篇的范围里。

GPT 中转站的特别之处：分数都很高

Veridrop 是一个开源的中转站检测工具。它公开的数据里，OpenAI 协议的情况是这样的（截至 2026 年 11 月 24 日）：

项目 数字
检测过的 OpenAI 中转站 6,643 家
OpenAI 协议的检测报告 76,734 份
进入排名的站 3,886 家
进入排名的站里，中位分 70 分以上的 98%
进入排名的站里，出现过严重问题的 14%

98% 的站分数过线，看上去几乎都没问题。但同时有 14% 出现过严重问题。两个数放在一起，说明一件事：GPT 中转站不能只看分数。

什么是“严重问题”

有的中转站把 GPT 请求转给别家模型，再把响应改成 OpenAI 的格式。改格式的时候，用量字段里常会留下别家接口才有的东西。

官方 Chat Completions 的 usage 里是 prompt_tokens、completion_tokens、total_tokens。出现下面这些，就说明请求被转过手：

usage 里出现 说明
claude_ 开头的字段 背后是 Claude 的接口
prompt_token_count、candidates_token_count 这类字段 背后是 Gemini 的接口
usage_source，值不是 openai 中转站自己写明了上游是别家

这类站的其他检测项可能都能过，分数照样很高。所以 Veridrop 的规则是：出现严重问题的报告，最高只能判“勉强”，不管分数多少。

想自己看一眼，发一条请求就行：

curl -s https://你的中转站地址/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "content-type: application/json" \
  -d '{
    "model": "你买的模型名",
    "messages": [{"role": "user", "content": "Reply with exactly: ok"}]
  }'

另外提醒一句：响应里的 model 字段写着 gpt，证明不了什么。这个字段中转站可以随便填。

各项检测的通过率

Veridrop 对 OpenAI 协议测 8 项。截至 11 月 24 日的通过率，括号里是 10 月 29 日：

检测项 查什么 通过率
基础请求 能不能正常返回 99%（98%）
模型一致性 是不是声称的那个模型 97%（96%）
函数调用 能不能按格式调用工具 91%（90%）
结构化输出 严格 JSON 格式能不能遵守 98%（98%）
协议字段 响应结构和官方是否一致 96%（96%）

用量计费 token 数是否对得上 60%（60%）

最低的两项是用量计费和长上下文。前一项关系到钱有没有多扣，后一项关系到长输入有没有被截短。

接 Codex，多看两项

Codex 干活时会频繁调用工具，并且要求严格的输出格式。所以给 Codex 选中转站，除了模型要是真的，还要看函数调用和结构化输出。这两项不稳，任务会跑到一半报格式错误。

Veridrop 给 Codex 单独列了一份名单，入选条件：

  • 在 OpenAI 榜进入排名；
  • 函数调用和结构化输出的通过率都在 80% 以上，每项至少测过 2 次；
  • 最近 30 天内测过。

截至 11 月 24 日，名单列满了 30 家。名单每天更新，当天的见 Codex 中转站名单。

Codex 怎么接

按 Codex 的官方说明，接中转站要在 ~/.codex/config.toml 里加一个自定义供应商：

model = "你买的模型名"
model_provider = "relay"

[model_providers.relay]
name = "relay"
base_url = "https://你的中转站地址/v1"
env_key = "RELAY_API_KEY"
wire_api = "responses"

env_key 写的是环境变量的名字，key 本身放在这个环境变量里。

注意 wire_api：Codex 的自定义供应商走的是 Responses 接口。只支持 Chat Completions 的中转站接不上，或者功能不全。充值之前先问清楚这一条。

检测没有覆盖的

这一点要说清楚：Veridrop 测的是 OpenAI 协议的真实性和上面这几项能力，没有专门测 Responses 接口是否完整可用。所以检测通过、进了名单，说明的是“这家站的 GPT 看起来是真的，工具调用也稳定”，不等于“一定能接上 Codex”。

接完以后的三步

  1. 用同样的地址、key 和模型名，在 Veridrop 上测一次，一分钟左右出结果，免费。
  2. 在 Codex 里跑一个需要读文件、调工具的小任务，看会不会中途报格式错误。
  3. 过一段时间再测一次。中转站可能会换后端。
